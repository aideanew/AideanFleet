# 六节报告模板（契约，FROZEN v1）

> 由工作包 FLEET-BE-01（角色A）产出，配合 [`docs/契约/任务状态机.md`](../docs/契约/任务状态机.md) 使用。
> 执行体（角色C 的适配器）完成任务后必须按本模板回执；`fleet/manager/report.py` 会按标题解析这六节，
> 少任何一节都会被判为不完整（`MissingReportSection`），不得进入审查。
> 机器可解析要求：**每一节的标题必须原样出现一次**（允许 `##` / `**` / `1.` 等前缀，但标题文字不得改写）。

---

## 1. 改动清单

| 文件 | 修改内容 | 修改原因 | 影响范围 |
|---|---|---|---|
| 相对路径 | 一句话说清改了什么 | 为什么改 | 可能影响谁 |

- 未改动任何文件时也要保留本节并写 `（无改动）`，不得删除本节。

## 2. 命令记录

按实际执行顺序记录**真实命令原文**与关键输出摘要（失败的命令必须原样保留，不得删改）：

```text
$ <命令>
<关键输出（含退出码）>
```

## 3. 证据链

| 编号 | 验证目标 | 文件/模块 | 命令或操作 | 关键结果 | 支持的结论 | 限制 |
|---|---|---|---|---|---|---|
| EV-1 | | | | | | |

- 证据文件路径必须与 `evidence_path` 一致，且真实存在、非空。
- "已完成""应该没问题""本地正常"这类表述**不能单独作为证据**（`docs/管理员全局设定示例.txt` §六）。

## 4. 四要素

> 本节的"四要素"口径为角色A 定稿：每一项主张都要能回答这四个问题，
> 依据是 `docs/管理员全局设定示例.txt` §六（目标 / 命令或操作 / 关键输出 / 支持的结论）。

| 要素 | 内容 |
|---|---|
| ① 目标 | 这一步想证明什么（可验证的命题，不是"我做完了"） |
| ② 命令或操作 | 具体执行了什么（命令原文或操作步骤） |
| ③ 关键输出 | 真实输出原文（失败也必须贴原文；长文本可截尾但需注明） |
| ④ 结论与限制 | 该输出支持什么结论，以及**不能**证明什么 |

## 5. 未完成事项

- 逐条列出：未做的事情、已知缺口、未验证的路径、被跳过的测试。
- 完全没有时写 `（无）`；**不得隐瞒**。

## 6. 模型自述

| 项 | 值 |
|---|---|
| 平台(provider) | 例：modelscope |
| 模型(model_id) | 例：ZhipuAI/GLM-5.2 |
| 网关/角色 | 例：worker / be-1 |
| 是否发生降级 | 是/否；若"是"，写 `from -> to` 与尝试次数 |
| 回复真实性 | 真实命中 / 超时重试 / 被阻塞 |
