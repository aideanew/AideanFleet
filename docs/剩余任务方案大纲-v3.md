## P1 契约缺口修复（可并行执行）

> 这些是设计已定义但实现未接通的缺口。

### P1-A stream_chunk 流式管道接通

#### P1-A-1 在 BaseAdapter 契约新增 run_stream 方法

- **动因**：`contracts.py:223` 的 `run()` 签名冻结，不能加参数；但流式需要回调通道。正确做法是新增方法，不破坏旧签名
- **操作**：在 `BaseAdapter` 上加 `def run_stream(self, prompt, workdir, model, timeout=600, on_chunk=None) -> AgentResult:`，默认实现直接调 `self.run(prompt, workdir, model, timeout)` 忽略 on_chunk
- **联动文件**：`fleet/manager/contracts.py`、`fleet/executors/base.py`
- **验收标准**：`BaseAdapter().run_stream(...)` 不抛异常，返回 AgentResult；所有现有适配器不改动仍正常工作

#### P1-A-2 FakeAdapter 实现 run_stream 吐假块

- **动因**：不花真钱就能测流式管道
- **操作**：覆写 `run_stream()`，分 3 次调用 `on_chunk("Fake chunk N/3")`，每次 sleep 0.05s，最后返回正常 AgentResult
- **联动文件**：`fleet/executors/fake.py`
- **验收标准**：单测中 `chunks = []; fake.run_stream(..., on_chunk=chunks.append)` → `len(chunks) == 3`

#### P1-A-3 dispatcher 调用 run_stream 并产出 stream_chunk 事件

- **动因**：dispatcher 当前只调 `adapter.run()`（`dispatcher.py:208`），不产 stream_chunk 事件 → 前端 ChatPage 的流式气泡永远收不到数据
- **操作**：在 `_run_with_chain()` 中，检测 `adapter.capabilities().streaming` 为 True 时调 `run_stream(on_chunk=callback)`；callback 内调用 `events.append(action="task:stream_chunk", ...)`；streaming 为 False 时 fallback 到 `run()`
- **联动文件**：`fleet/manager/dispatcher.py`、`fleet/core/events.py`
- **验收标准**：用 FakeAdapter 跑一个任务 → `data/events.jsonl` 中出现 `task:stream_chunk` 事件

#### P1-A-4 前端 ChatPage 消费 stream_chunk（已有代码，验证即可）

- **动因**：前端 ChatPage 已有 stream_chunk 处理逻辑（`ChatPage.vue` 中的 stream_chunk case），只是后端不产出所以无法验证
- **操作**：P1-A-3 完成后，启动控制台 + 跑一个 FakeAdapter 任务 → 检查前端是否出现流式气泡
- **联动文件**：`fleet/console/web/src/components/ChatPage.vue`（验证不改）
- **验收标准**：前端聊天界面出现逐步增长的文本气泡

### P1-B intake 模板 allowed_files 预填

#### P1-B-1 在 _plan_templates 中为每个任务预填 allowed_files

- **动因**：`intake.py:247` 所有任务 `allowed_files=""` → DAG `_allowed_patterns` 回退为 `["*"]` → `_ranges_conflict(["*"],["*"])` 返回 True → 同阶段并行任务被强制串行
- **操作**：在 `_plan_templates()` 返回的每个 spec 字典中加 `"allowed_files"` 字段：
  - 技术设计：`docs/**`
  - 核心引擎：`src/**,index.html,package.json,tsconfig.json`
  - 界面实现：`src/components/**,src/styles/**,index.html`
  - 集成验收：`src/**,index.html,docs/**`
  - 终局验收：`docs/**`
- **联动文件**：`fleet/manager/intake.py`
- **验收标准**：单测中 `start_project()` 后检查 task 行的 `allowed_files` 字段非空；`_ranges_conflict` 对同阶段两个任务返回 False

#### P1-B-2 DAG 对全通配模式增加警告而非死锁

- **动因**：用户自定义任务可能不填 allowed_files（留空 → `["*"]`），两个 `["*"]` 任务会被判定冲突 → 串行。不应死锁，但应提醒
- **操作**：在 `dag.py` 的 `_ranges_conflict` 调用处，当双方均为 `["*"]` 时，发一个 `task:range_unrestricted` 警告事件但仍允许并行
- **联动文件**：`fleet/manager/dag.py`
- **验收标准**：两个 allowed_files 为空的任务在同阶段 → 并行执行 + events.jsonl 中出现 range_unrestricted 警告

### P1-C 前端健壮性

#### P1-C-1 修复 useWebSocket.ts 空 catch 块

- **动因**：`useWebSocket.ts` 中 `catch {}` 空块静默吞掉所有错误，断线重连失败时无任何日志

#### P1-C-2 修复 on_event 弃用警告

- **动因**：`server.py:1293` 使用 `@app.on_event("startup")`，FastAPI/Starlette 已标记弃用，每次启动打印 DeprecationWarning
- **操作**：改为 `lifespan` 上下文管理器（`@asynccontextmanager`），将 startup 和原 shutdown 逻辑移入

## P2 性能优化（可并行执行）

> 不阻断功能，但影响用户体验和系统吞吐。

### P2-A 事件流优化

#### P2-A-1 事件序列游标持久化

- **动因**：当前事件序列号在内存中递增，进程重启后从 0 开始 → 前端 `GET /api/events?since=<seq>` 拿到重复事件
- **操作**：将 `events.jsonl` 的最后一行 seq 号作为启动时的初始值；或在 db 中记录 `event_seq` 计数器
- **联动文件**：`fleet/core/events.py`、`fleet/core/db.py`
- **验收标准**：发几个事件 → 重启服务端 → 新事件的 seq 号继续递增（不归零）

#### P2-A-2 WS 广播过滤（按 project_id）

- **动因**：当前 WS 广播所有事件给所有连接的客户端，多项目场景下客户端收到无关项目的事件
- **操作**：在 WS broadcast 时，根据客户端订阅的 project_id 过滤事件
- **联动文件**：`fleet/console/server.py`（WS broadcast 逻辑）
- **验收标准**：项目 A 的事件不出现在只订阅项目 B 的 WS 连接中

### P2-B 前端性能

#### P2-B-1 聊天历史虚拟滚动

- **动因**：ChatPage 当前全量渲染所有消息气泡，消息超过 100 条时明显卡顿
- **操作**：引入虚拟列表（如 `vue-virtual-scroller`），只渲染可视区域 ±缓冲区的消息
- **联动文件**：`fleet/console/web/src/components/ChatPage.vue`、`fleet/console/web/package.json`
- **验收标准**：模拟 500 条消息 → 页面滚动流畅（FPS > 30）；DOM 节点数 < 50

## 决策点结论汇总

| 编号 | 决策 | 结论 | 理由 |
|------|------|------|------|
| D1 | 凭据处理方式 | 换锁 + 重写历史（乙方案） | 仓库 public + 仅 3 commit + 0 协作者，重写成本极低 |
| D2 | dist/ 入库 | 不入库 + 服务端检测 + Makefile 引导（甲方案+安全网） | minified 文件每次构建 hash 变，入库污染 git 历史 |
| D3 | FakeAdapter on_chunk | 新增 run_stream 方法，不改 run 签名 | run() 签名冻结，扩展优于修改 |
| D4 | intake allowed_files | 预填合理默认 + DAG 对全通配发警告不死锁 | 预填恢复并行能力，兜底防死锁 |
| D5 | MockWriteAdapter | P2 级别做，不阻断当前安全修复 | 解锁无 LLM 端到端测试 |
| D6 | prompts 目录分裂 | 合并到 fleet/prompts/ | 唯一被打包的目录，消除路径断裂 |
