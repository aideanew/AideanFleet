✅ 采纳。统一`startProject(request)`入口，以后增加任何新入口都只需增加Adapter。

✅ 采纳。一个Execution Engine，Policy参数控制行为。

**M1-用户对话是Control Plane，不是普通Chat**

**M1-HumanDecisionRequired正式状态**

```python
VALID_TRANSITIONS = {
    "DRAFT": ["ASSIGNED"],
    "ASSIGNED": ["DOING"],
    "DOING": ["SUBMITTED"],
    "SUBMITTED": ["REVIEWING"],
    "REVIEWING": ["DONE", "PARTIAL", "REWORK", "BLOCKED"],
    "REWORK": ["ASSIGNED"],
    "BLOCKED": ["ASSIGNED"],  # 人工解除后重新分配
    "ESCALATED": ["ASSIGNED"],
    "PARTIAL": ["DONE"],  # 缺口修复后
}
```
- `transition(task_id, from_status, to_status)`：验证合法性，更新DB，追加事件，更新updated_at
- 任何非法迁移抛`InvalidTransitionError(from_status, to_status)`，不落库，不写事件
- REWORK状态变更时同步rework_count+1；rework_count>3时自动迁移到ESCALATED

#### 9.3.2 数据库初始化（db.py）
- 应用启动时`CREATE TABLE IF NOT EXISTS`（不覆盖已有数据）
- 提供TaskRepository类：
  - `create_task(**fields) -> task_id`
  - `get_task(task_id) -> dict`
  - `update_task(task_id, **fields)`（不经状态机的字段更新，如token_used、detail）
  - `list_tasks(project_id, status=None, page=1, page_size=20) -> list`
  - `get_ready_tasks(project_id) -> list`（返回所有ASSIGNED状态且依赖全部DONE的任务）
- 所有方法同步（SQLite不需要async），通过线程锁保证并发安全

#### 9.3.3 事件流（events.py）
- append-only写入`data/events.jsonl`，一行一个JSON
- 每行结构：`{"seq":N,"timestamp":"ISO8601","project_id":"...","actor":"...","action":"...","task_id":"...","summary":"...","extra":{}}`
- seq全局单调递增（基于文件行数+1）
- `append_event(**fields)`：获取文件锁 → 写入 → 释放锁（防并发写入损坏）
- `read_events_since(project_id, since_seq) -> list`：增量读取，返回seq>since_seq的所有事件
- 任何代码不得删除或修改已写入的行

### 9.4 模型池与调度（fleet/models/）

#### 9.4.1 模型池加载（pool.py）
- 解析.env模型池段（MODEL_N_前缀），构建Model列表
- 按level升序排列（数字小=优先级高）
- `get_models_for_role(role_name) -> list[Model]`：返回该角色bind_model_name绑定的模型列表，按bind顺序（而非level，bind顺序即fallback顺序）

#### 9.4.2 重试策略（retry.py）
```python
HARD_FAIL_CODES = {"401", "402", "403", "quota_exhausted", "model_not_found"}
SOFT_RETRY_CODES = {"429", "TIMEOUT"}
MAX_SOFT_RETRIES = 10  # 从EnvConfig读取
RETRY_WAIT_SECONDS = 10  # 从EnvConfig读取
```
- 软失败（429/TIMEOUT）：等待RETRY_WAIT_SECONDS，重试，最多MAX_SOFT_RETRIES次
- 硬失败（HARD_FAIL_CODES）：立即切换，不空耗重试次数
- 当前模型全部尝试耗尽→切换到列表下一个模型，追加事件`model:switch`（含from/to/attempts/reason）
- 所有模型耗尽→返回BLOCKED状态，附每个模型的失败原因

#### 9.4.3 模型路由器（router.py）
- `async call(role_name, messages, stream=False) -> ModelCallResult`
- 内部按role的bind_model_name列表依次尝试，失败按retry.py策略处理
- 每次成功调用记录：model_name、token_used、duration_ms，写事件`model:call`
- 额度不足时追加事件`model:quota_exhausted`，触发邮件通知检查

### 9.5 Manager引擎（fleet/manager/）

#### 9.5.1 核心设计原则
Manager是系统组件，不是单纯的LLM调用。结构：
```
Manager
├── ManagerLLM（调用模型路由器，负责"思考"）
├── DAGEngine（判断READY/BLOCKED/依赖，Python代码，不经LLM）
├── Scheduler（选择READY任务→分配给角色→调用执行体）
├── Reviewer（接收六节报告→触发Machine Gate→触发审查角色）
└── ReworkManager（审查不通过→生成返工任务包→重新派工）
```

#### 9.5.2 DAG引擎（dag.py）
- `get_ready_tasks(project_id) -> list[Task]`：纯Python逻辑判断
  - 条件：exec_status=ASSIGNED 且 所有dependencies中的task_id状态为DONE
  - 检查冲突：allowed_files/forbidden_files是否与当前DOING任务冲突
- `release_dependents(completed_task_id)`：某任务DONE后，检查依赖它的任务是否全部满足，满足则释放（不改状态，Scheduler读取后决定是否立即分配）
- `detect_cycles(task_dependencies) -> bool`：拓扑排序检测依赖环，建立任务时调用

#### 9.5.3 调度器（scheduler.py）
- `async schedule_once(project_id)`：获取READY任务列表→按角色可用性分配→调用dispatcher.py
- `async run_loop(project_id, mode)`：持续调度循环
  - mode=auto：有READY任务立即调度
  - mode=step：READY后等待确认事件（`confirm_step`）再调度
  - 无READY任务时等待500ms再检查（asyncio.sleep，不轮询DB）

#### 9.5.4 派工器（dispatcher.py）
```
输入TaskPack
    ↓
状态DRAFT→ASSIGNED（写DB+写事件）
    ↓
调用BaseAdapter.run(prompt, workdir, model, timeout)
    ↓（等待结果）
状态ASSIGNED→DOING→SUBMITTED（写DB+写事件）
    ↓
触发Machine Gate（gates/verify.py）
    ↓（Gate结果）
触发审查角色（同走模型路由器）
    ↓
状态SUBMITTED→REVIEWING→DONE/REWORK/BLOCKED
```
- TaskPack结构（生成prompt的原材料）：
  ```python
  class TaskPack:
      task_id: str
      title: str
      detail: str           # 任务详细描述
      verify_cmd: str       # 机器验收命令
      assignee_role: str    # 执行角色名
      reviewer_role: str    # 审查角色名
      workspace: str        # 工作目录绝对路径
      allowed_files: list   # 允许修改的文件列表（空=无限制）
      forbidden_files: list # 禁止修改的文件列表
      context: dict         # 上下文信息（依赖任务的输出摘要）
      rework_reason: str    # 返工原因（首次为空）
  ```

#### 9.5.5 审查器（reviewer.py）
- 将执行结果（六节报告）传给审查角色
- 审查角色只能返回四个值之一：PASS/PARTIAL/REWORK/BLOCKED
- 非法返回值：重新请求审查角色（最多3次），仍非法→记为REWORK
- 审查结果写入DB的review_result字段，更新exec_status

#### 9.5.6 返工管理器（rework_manager.py）
- REWORK时：读取原任务+审查意见→生成新的TaskPack（rework_reason填入审查意见）→走完整派工流程
- rework_count>3时触发ESCALATED，追加事件`task:escalated`，不再自动重新派工
- ESCALATED任务等待人工通过控制台确认后（POST /api/control/confirm带task_id）重新ASSIGNED

### 9.6 Machine Gate（fleet/gates/verify.py）

#### 9.6.1 Gate执行逻辑（在LLM审查之前强制执行）
```python
class MachineGate:
    def run(self, task: Task, result: AgentResult) -> GateResult:
        # 1. verify_cmd执行
        if task.verify_cmd:
            exit_code, stdout = run_cmd(task.verify_cmd, cwd=task.workspace, timeout=60)
            if exit_code != 0:
                return GateResult(FAIL, reason=f"verify_cmd exit_code={exit_code}", output=stdout[:2000])
        
        # 2. 禁改文件扫描
        if task.forbidden_files:
            modified = get_git_modified_files(task.workspace)
            violations = [f for f in modified if f in task.forbidden_files]
            if violations:
                return GateResult(FAIL, reason=f"修改了禁止文件: {violations}")
        
        # 3. 证据文件存在性检查
        if expected_evidence := task.detail.get("expected_files", []):
            missing = [f for f in expected_evidence if not Path(task.workspace/f).exists()]
            if missing:
                return GateResult(FAIL, reason=f"证据文件缺失: {missing}")
        
        return GateResult(PASS)
```
- GateResult.FAIL直接触发REWORK，Manager LLM无权改判（这是系统硬规则）
- Gate结果写事件`gate:pass`或`gate:fail`（含verify_cmd原始输出截尾2000字）
- Gate失败不调用审查角色，直接走返工流程

#### 9.3.1 各Store定义

#### 9.3.2 WebSocket客户端（src/composables/useWebSocket.ts）
```ts
// 核心逻辑
const connect = () => {
  ws = new WebSocket(`ws://${location.host}/ws`)
  ws.onmessage = (e) => dispatch(JSON.parse(e.data))
  ws.onclose = () => scheduleReconnect()  // 指数退避，最大30秒
}

const dispatch = (msg: WsMessage) => {
  switch(msg.type) {
    case 'task_update': useTaskStore().updateTask(msg)
    case 'plan_update': usePlanStore().setPlan(msg.plan)
    case 'progress': useProgressStore().setStep(msg)
    case 'stream_chunk': useChatStore().appendChunk(msg)
    case 'chat_message': useChatStore().addMessage(msg)
    case 'notification': showToast(msg)
    case 'config_changed': useConfigStore().reload(msg.section)
  }
}
```

WebSocket断线时降级为轮询：每秒调用GET /api/events?since=<lastSeq>，
收到events后复用dispatch函数（消息格式与WebSocket一致）。

from typing import Optional

@dataclass
class AgentResult:
    ok: bool

#### 9.2.2 四个适配器的共同行为规范
每个适配器都必须：
1. **Capability Discovery**：构造时执行`<cmd> --help`，解析支持的参数，存入Capabilities数据类；
   `check_available()`返回是否可探测到CLI
2. **子进程调用**：使用asyncio.create_subprocess_exec（支持async/await）
   - cwd=workdir，超时到时调用`proc.kill()`并等待进程树结束
   - 超时判断：`asyncio.wait_for(proc.wait(), timeout=timeout)`
3. **错误码映射**：
   - stderr或stdout含"429" → error_code="429"
   - 含"401"或"unauthorized" → error_code="401"
   - 含"quota"或"insufficient_quota" → error_code="401"（触发直接切换）
   - 进程超时 → error_code="TIMEOUT"
   - 进程exit_code!=0且无上述关键词 → error_code="TOOL_FAIL"
4. **证据保存**：完整原始stdout+stderr写入`data/evidence/<task_id>/attempt-<N>.log`
   （不截尾、不修改；AgentResult.output是截尾后的摘要供上层读取）
5. **Windows兼容**：子进程创建加`creationflags=subprocess.CREATE_NEW_PROCESS_GROUP`；
   所有路径使用`pathlib.Path`

### 9.6 邮件通知模块（fleet/notify/）

#### 9.6.1 SMTP发送（smtp.py）
```python
import smtplib
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart
from email.header import Header
import asyncio

class EmailNotifier:
    def _load_config(self):
        """每次发送前实时读取.env，防止配置变更失效"""
        from fleet.core.config import EnvConfig
        cfg = EnvConfig()
        return cfg.load("email")  # 返回EMAIL_*段的所有配置
    
    async def send(self, subject: str, body: str) -> bool:
        """异步发送（run_in_executor，不阻塞主线程）"""
        return await asyncio.get_event_loop().run_in_executor(
            None, self._sync_send, subject, body
        )
    
    def _sync_send(self, subject: str, body: str) -> bool:
        cfg = self._load_config()
        try:
            msg = MIMEMultipart()
            msg['From'] = cfg['EMAIL_SENDER']
            msg['To'] = cfg['EMAIL_RECEIVER']
            msg['Subject'] = Header(subject, 'utf-8')
            msg.attach(MIMEText(body, 'plain', 'utf-8'))
            
            with smtplib.SMTP_SSL(cfg['EMAIL_SMTP_HOST'], int(cfg['EMAIL_SMTP_PORT'])) as smtp:
                smtp.login(cfg['EMAIL_SENDER'], cfg['EMAIL_PASSWORD'])
                smtp.sendmail(cfg['EMAIL_SENDER'], cfg['EMAIL_RECEIVER'], msg.as_string())
            
            # 写成功事件
            append_event(actor="notify", action="notify:sent", summary=f"邮件已发送: {subject}")
            return True
        except Exception as e:
            append_event(actor="notify", action="notify:failed", summary=f"邮件发送失败: {str(e)[:100]}")
            return False
```
