6. TASK STATE MACHINE
==================================================

Use only valid transitions:

DRAFT -> ASSIGNED
ASSIGNED -> DOING
DOING -> SUBMITTED
SUBMITTED -> REVIEWING
REVIEWING -> DONE
REVIEWING -> PARTIAL
REVIEWING -> REWORK
REVIEWING -> BLOCKED
REWORK -> ASSIGNED
FAILED -> ASSIGNED
BLOCKED -> ASSIGNED only after the dependency is actually resolved

Do not manually jump from DRAFT to DONE.
Do not treat ASSIGNED or READY as completed.
Do not treat a worker’s natural-language claim as machine verification.

After every dispatch:
- confirm ASSIGNED;
- confirm DOING;
- wait for SUBMITTED;
- collect the worker report;
- run the machine gate;
- send to reviewer;
- collect reviewer verdict;
- transition only according to the valid state machine.

==================================================
8. RETRY POLICY
==================================================

Retry only dispatch/transport failures, not arbitrary implementation failures.

Classify failures:

A. Gateway unavailable:
- wait 10 seconds;
- recheck role agent-card;
- start/reuse the gateway;
- retry the same task package once.

B. Manager/A2A timeout:
- wait 60 seconds;
- retry the exact same context once;
- do not create a duplicate task;
- do not send a modified fake success prompt.

C. Worker reports test failure:
- send to reviewer only if the task package permits review of partial work;
- otherwise return REWORK with the exact failed command output.

D. Machine gate failure:
- do not mark DONE;
- return REWORK;
- include failed output;
- retry maximum 3 total rework cycles.

E. External dependency unavailable:
- mark BLOCKED;
- include exact dependency, command output, and who must resolve it;
- continue independent tasks.

Never silently discard an error.
Never convert TIMEOUT into DONE.
Never convert BLOCKED into DONE.
