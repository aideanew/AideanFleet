| # | 现象 | 根因 |
|---|---|---|
| 1 | 显示 3/5 而非 5/5；"已完成"仍在计时 | **3/5 是真实状态**：T04=BLOCKED（执行体反复起本地服务器触发 stuck 检测）、T05=ASSIGNED 未执行。前端只显示 "3/5" 无状态拆解，用户无从知道差在哪；已执行时间从 run_started_at 持续计时，100% 前一直走，语义无问题但缺"未完成原因"说明 |
| 2 | 看不到历史任务详情 | 后端 `GET /api/tasks/{id}` 已存在（server.py:779），前端 `api.getTask` 已封装，但 Overview 任务行不可点击，无详情入口 |

## 1 方案大纲

### L1-A 用量真实化（执行体 token 上报）
- 1.1 `fleet/executors/opencode.py`：抽纯函数 `parse_opencode_json_output(stdout) -> (text, usage)`——拼接 `text` part 为输出，取最后一个 `step_finish.part.tokens`（input/output/reasoning/total）为 usage；无 usage 时 `(原样输出, None)`。
- 1.2 `run()` 改用 `--format json`，输出与 usage 走 1.1；usage 经 AgentResult.usage → dispatcher `token=result.usage` 落库（链路已存在，无需改 dispatcher）。
- 1.3 测试：`tests/core/test_opencode_usage.py`（canned JSON，不依赖真实 CLI）：多 text 拼接、tokens 提取、非 JSON 降级、空输出。

### L1-B 角色贡献聚合 API
- 2.1 `fleet/console/server.py` 新增 `GET /api/roles/summary?project=`：按任务聚合 `assignee → {任务数, DONE数, duration_ms 合计, token 合计, call_count}`；token 来源 UsageAggregator.by_task（模型调用）+ 任务行 token 字段（执行体上报）合并去重（以事件 model:call 为准，执行体 usage 落在任务行 token 列）。
- 2.2 测试：`tests/core/test_roles_summary.py`（TestClient，含空项目 404/200 语义）。

### L1-C 前端可观测性
- 3.1 Overview 指标区：任务完成旁新增状态拆解徽标（完成 n · 执行中 n · 阻塞 n · 待派 n），3/5 一眼看出差在哪。
- 3.2 任务详情：Overview/ProgressRail 任务行可点击 → Modal 展示 `/api/tasks/{id}` 详情（状态机轨迹、report_path、duration、model、rework_count）。
- 3.3 角色贡献卡片（Overview 页）：渲染 2.1 数据（角色/任务数/耗时/Token）。
- 3.4 计时语义：percent>=100 时 elapsed 冻结为最后任务完成时间差并标注"已收口"。

### L1-D 项目身份收口
- 4.1 `cli_start.py`：默认项目名 = 项目路径 basename（不再硬编码 AideanFleet）。
- 4.2 TopBar Logo 右侧显示当前项目名（auth.project 对应 name），非静态 "AideanFleet"。
- 4.3 切换加固：switchProject 成功后重置 connection.lastSeq=0 并重拉事件，防旧项目事件串台。
- 4.4 测试：`tests/test_cli_launch.py` 增默认名推导用例。

### L1-E 验收
- 5.1 后端：新增测试全绿 + 全量回归。
- 5.2 前端：vue-tsc + build。
- 5.3 浏览器实测：3/5 带状态拆解；点任务出详情；角色卡片有真实 token/耗时；Logo 显示 Test09171500；下拉切换正常（截图）。
- 5.4 docs 需求映射：完成后在核验版大纲勾选 W1.8/W6 对应项。
