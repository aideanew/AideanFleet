============================================================
项目开发 - 多方案评审标准指令
============================================================
版本：v1.0  日期：2026-09-24
适用项目：AideanFleet
适用场景：开发阶段的技术选型、架构变更、依赖引入
核心原则：性能最优 + 初中生都能完成开发的最简流程

------------------------------------------------------------
一、适用范围
------------------------------------------------------------

本指令适用于 AideanFleet 开发阶段的以下场景：
  - 新增外部依赖（pip/npm 包）
  - 新增模块或重命名模块
  - 修改 FROZEN 契约
  - 引入新的设计模式或架构模式
  - 任何影响启动流程或端口配置的变更

不适用场景（直接执行，无需评审）：
  - Bug 修复（不改变接口语义）
  - 测试用例新增或修复
  - 文档更新
  - 配置文件调整（.env.example）

------------------------------------------------------------
二、开发阶段评审清单
------------------------------------------------------------

在提交代码前，逐项检查：

### 2.1 简单性检查
  [ ] 新增代码不超过 200 行（不含测试）？
  [ ] 新增依赖不超过 1 个？
  [ ] 新增概念不超过 2 个？（需要在 ADR 中解释）
  [ ] 初中生能看懂主要逻辑？

### 2.2 契约兼容性检查
  [ ] 是否修改了 FROZEN 契约？（如是→停止，需全体签字）
  [ ] 状态机迁移表是否变化？（如是→同步改契约+测试）
  [ ] API 端点是否新增/删除？（如是→更新控制台API.md）
  [ ] 事件格式是否变化？（如是→更新events-format.md）

### 2.3 性能检查
  [ ] 新增 I/O 操作是否批量处理？
  [ ] 新增循环是否有 O(n²) 风险？
  [ ] 新增 import 是否在模块顶层？
  [ ] SQLite 写操作是否在事务内？

### 2.4 安全检查
  [ ] 用户输入是否经过验证？
  [ ] 密钥/Token 是否通过环境变量传入？（不写入 .tf/.py）
  [ ] 文件路径是否经过路径注入检查？
  [ ] events.jsonl 写入前是否过 scrub()？

### 2.5 可回滚检查
  [ ] 变更是否可通过 git revert 回滚？
  [ ] 是否有数据库迁移？（如有→提供 downgrade 脚本）
  [ ] 是否修改了 data/ 目录结构？（如有→提供迁移脚本）

------------------------------------------------------------
三、依赖引入评审标准
------------------------------------------------------------

新增 Python 包必须满足：

  1. 纯 Python 或有 aarch64 wheels（项目运行在 ARM64）
  2. 安装不需要系统级依赖（如 libxml2、libffi）
  3. 包大小 < 10MB
  4. 月下载量 > 10万（社区活跃度）
  5. 不与现有依赖冲突

不满足任一条 → 评审拒绝，寻找替代方案。

当前允许的外部依赖（pyproject.toml + requirements.txt）：
  - fastapi, uvicorn, starlette, pydantic  （Web 框架）
  - websockets, uvloop, httptools           （性能加速）
  - pyyaml, python-dotenv                   （配置解析）
  - httpx, certifi                          （HTTP 客户端）
  - watchfiles                              （文件监控）

------------------------------------------------------------
四、模块边界规则
------------------------------------------------------------

  fleet/core/       — 控制面核心（状态机、DB、事件、计划）
    ↓ 不允许 import fleet/manager/ 或 fleet/console/
  fleet/manager/    — Manager 逻辑（调度、派工、intake）
    ↓ 可以 import fleet/core/
    ↓ 不允许 import fleet/console/
  fleet/console/    — 控制台服务（FastAPI + WS）
    ↓ 可以 import fleet/core/ 和 fleet/manager/
  fleet/executors/  — 执行体适配器
    ↓ 可以 import fleet/manager/contracts.py（单向）
  fleet/launcher/   — 启动器
    ↓ 可以 import 所有模块（启动入口）
  fleet/notify/     — 通知器
    ↓ 独立模块，最小依赖

违反依赖方向 = 评审不通过。

------------------------------------------------------------
五、代码评审三问
------------------------------------------------------------

每次提交前自问：

  Q1: 如果这段代码出了 bug，最坏情况是什么？
      → 如果是"数据丢失"或"状态机损坏"，必须有防御代码

  Q2: 如果一个初中生接手这段代码，他需要知道什么？
      → 需要知道的东西必须写在注释或文档里

  Q3: 如果删掉这段代码，系统会怎样？
      → 如果"没有影响"，这段代码就不应该存在

------------------------------------------------------------
七、紧急变更流程
------------------------------------------------------------

  1. 先修复（可跳过评审）
  2. 24 小时内补评审记录
  3. 补测试用例
  4. 补文档更新
  5. commit message 标注 [HOTFIX]
