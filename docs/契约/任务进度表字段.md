### 2.1 上下文成本扩展列（v1.2 新增，CORE-04；列名与语义冻结）

TaskPack v1.2 三个可选字段的持久化列（[`控制台API.md`](./控制台API.md) §13.1）；旧库由 `db.init_db()` 轻量迁移自动补列。

| 列名 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `context_budget` | INTEGER | | 本任务 prompt 上下文 token 上限（估算口径 tokens≈chars÷4），默认 `8000`；`<300` 按缺省处理 |
| `memory_refs` | TEXT | | JSON 数组；允许引用的项目记忆条目 id（如 `["M-0001"]`）；空/缺省 = 不注入记忆头 |
| `retry_context` | TEXT | | JSON 对象；返工增量上下文 `{attempt, failure, previous_diff, evidence_paths}`，由返工管理器自动填充；派生数据，跨重启不保证保留 |

**字段一致性约束**：`CONTROL_PLANE_CONTRACT_FIELDS`（前 15 个）在 `fleet/core/db.py` 中以常量形式冻结，
并由 `tests/test_db.py::test_contract_fields_frozen` 断言，任何人改字段名都会让单测失败。

## 3. `exec_status` 枚举（= 任务状态机状态）

`DRAFT` | `ASSIGNED` | `DOING` | `SUBMITTED` | `REVIEWING` | `DONE` | `PARTIAL` | `REWORK` | `BLOCKED` | `ESCALATED`

- 合法迁移、终态、升级规则见 [`任务状态机.md`](./任务状态机.md)。
- 与 `初始设计/核心2.md` 的数字枚举映射见状态机文档 §4.1。

## 4. `review_status` 枚举

| 值 | 含义 | 写入时机 |
|---|---|---|
| `PENDING` | 尚未进入审查（含等待/执行中） | 建任务时默认 |
| `REVIEWING` | 审查中 | `SUBMITTED -> REVIEWING` |
| `PASS` | 审查通过 | `REVIEWING -> DONE` |
| `PARTIAL` | 部分通过 | `REVIEWING -> PARTIAL` |
| `REWORK` | 审查不通过，需重做 | `REVIEWING -> REWORK`，或机器门失败强制改判 |
| `BLOCKED` | 审查被阻塞 / 回执非法 | `REVIEWING -> BLOCKED` |

**只接受这 6 个值。** 审查角色回执若为 `PASS/PARTIAL/REWORK/BLOCKED` 以外的内容，一律记为 `BLOCKED` 且 `blocked_reason="invalid_review_verdict"`，
不得默认放行为 `PASS`（实现：`fleet/manager/reviewer.py`）。

## 6. 磁盘布局（三份契约共用的路径约定）

```text
<FLEET_ROOT>/
├── .env.example                 # 模板，禁止写入（运行期）
├── .env                         # 首次运行从 .env.example 复制，可读可写
├── data/
│   ├── fleet.db                 # SQLite：任务状态（本文件 §1/§2/§5）
│   ├── events.jsonl             # append-only 事件流（见 控制台API.md §3）
│   ├── memory/                  # v1.2 新增：Project Memory（原子写，不上传外部服务）
│   │   └── <project_id>.json    # 记忆条目 schema 见 控制台API.md §13.3
│   └── projects/<project_id>/
│       ├── plan.json            # 三级大纲规划（见 §7）
│       └── evidence/<task_id>/  # 机器门证据（stdout/exit_code/changed_files/report.md）
```

`FLEET_DATA_DIR` 可整体重定向（测试使用临时目录，避免污染 `data/`）。

## 7. `plan.json` 结构（字段名冻结）

```json
{
  "project": "P-001",
  "updated_at": "2026-09-15T13:20:31+08:00",
  "阶段": [
    {
      "名称": "阶段0 契约与地基",
      "任务": [
        {
          "子任务": "写三份契约文件",
          "task_id": "T-001"
        }
      ]
    }
  ]
}
```

- 键名 `阶段` / `名称` / `任务` / `子任务` / `task_id` 冻结（`初始设计/核心2.md` 原文口径）。
- 顶层附加字段 `project`、`updated_at` 为扩展字段（用于控制台与 API 定位，不影响三级大纲语义）。
- 每次 Manager 分配后调用 `plan.update_task(project_id, stage, subtask, task_id)` 原子重写整个文件。
- 实现：`fleet/core/plan.py`，写盘方式为"临时文件 + `os.replace`"。
