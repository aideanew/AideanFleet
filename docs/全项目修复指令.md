## 二、需修复的三类问题

### 问题 A：GitHub Actions CI 持续失败（Python 3.12 + Windows）

**影响项目**：任何有 `.github/workflows/` 且跑 pytest 的项目。

#### 根因 1：Python 3.12 asyncio 时序竞态

Python 3.12 的 asyncio 事件循环调度比 3.11 更快。如果测试中有以下模式：

```python
# ❌ 危险模式：confirm 发送速率与 run_loop tick 速率存在竞态
async def drive():
    bus = ControlBus("step")
    task = asyncio.create_task(
        run_loop(bus, interval=0.01, max_ticks=6)  # 0.06 秒窗口
    )
    for _ in range(5):
        bus.confirm(note="放行")
        await asyncio.sleep(0.05)  # 0.05 秒发一次 = 比.tick 慢
    await task
```

在 Python 3.12 上，run_loop 在等待 confirm 期间快速空转消耗 tick，6 个 tick 只处理了 2 个 confirm，后续任务永远轮不到派工。Python 3.11 调度稍慢恰好掩盖了这个竞态。

**修复模式**：

```python
# ✅ 正确模式：预先发送全部 confirm，消除竞态
async def drive():
    bus = ControlBus("step")
    for _ in range(8):        # 预先全部发送
        bus.confirm(note="放行")
    task = asyncio.create_task(
        run_loop(bus, interval=0.01, max_ticks=12)  # 加大余量
    )
    await task
```

**通用规则**：任何涉及 asyncio + 定时器 + 外部信号的测试，都应预先填充信号而非逐个 sleep 发送。

#### 根因 2：Windows UnicodeEncodeError

Windows 控制台默认编码 cp1252，无法编码中文字符。测试 docstring、.env 注释、日志输出中的中文会触发：

```
UnicodeEncodeError: 'charmap' codec can't encode characters in position 25-28
```

**修复**：在 workflow 的 job 级别设置环境变量：

```yaml
jobs:
  test:
    runs-on: ${{ matrix.os }}
    env:
      PYTHONIOENCODING: utf-8
      PYTHONUTF8: "1"
```

#### 根因 3：CI 假绿（fail step 被 skip）

如果 workflow 中用 `if: always()` 或 `continue-on-error: true` 包装了测试步骤，但 fail-step 的条件写错，会导致测试失败但 job 报绿。

**正确写法**：

```yaml
- name: Run tests
  id: pytest
  run: python -m pytest tests --tb=short -q
  # 不加 continue-on-error，让步骤自然失败

- name: Fail job if tests failed
  if: steps.pytest.outcome == 'failure'
  run: exit 1
```

> 如果不需要调试，只需最简版本（不加 id/continue-on-error，pytest 失败自然终止 job）。

#### 完整标准 workflow 模板

```yaml
name: "测试"

on:
  push:
    branches: [main, dev]
  pull_request:
    branches: [main]

jobs:
  test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
        python-version: ['3.12']

    runs-on: ${{ matrix.os }}

    env:
      PYTHONIOENCODING: utf-8
      PYTHONUTF8: "1"

    steps:
    - uses: actions/checkout@v4

    - name: Set up Python ${{ matrix.python-version }}
      uses: actions/setup-python@v5
      with:
        python-version: ${{ matrix.python-version }}

    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt
        pip install -e .
      shell: bash

    - name: Run tests
      run: |
        python -m pytest tests --tb=short -q
      shell: bash
```

### 问题 C：推送权限（SSH 私钥 / Personal Access Token）

#### 方式 1：SSH 私钥 + 代理（用户首选）

```bash
# 1. 确认 SSH 配置（~/.ssh/config 或 C:\Users\<用户>\.ssh\config）
Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_ed25519    # 替换为实际私钥路径
  ProxyCommand connect -H 127.0.0.1:10808 %h %p   # Windows 用 connect
  # 或: ProxyCommand nc -X connect -x 127.0.0.1:10808 %h %p  # 如果有 nc

# 2. 切换 remote 从 HTTPS 到 SSH
cd E:\Code\<项目>
git remote set-url origin git@github.com:aideanew/<项目>.git

# 3. 测试连接
ssh -T git@github.com
# 期望: Hi aideanew! You've successfully authenticated...

# 4. 推送
git push origin main
```

#### 方式 2：Personal Access Token (PAT) + 代理

```bash
# 1. 在 GitHub 创建 PAT
#    Settings → Developer settings → Personal access tokens → Fine-grained tokens
#    权限: Contents (read/write), Metadata (read), Workflows (read/write)
#    有效期: 建议 90 天

# 2. 设置 remote URL 带 token（或用 credential helper）
git remote set-url origin https://<PAT>@github.com/aideanew/<项目>.git

# 3. 配置 git 代理
git config --global http.proxy http://127.0.0.1:10808
git config --global https.proxy http://127.0.0.1:10808

# 4. 推送
git push origin main
```

#### 方式 3：SSH over HTTPS（端口 443，绕过 22 被墙）

```bash
# ~/.ssh/config
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519
  ProxyCommand connect -H 127.0.0.1:10808 %h %p
```

## 六、注意事项

1. **不要在 Linux 沙箱执行**：这些项目在 `E:\Code\` 下，只能在 Windows 本地操作。
2. **git filter-repo 会重写历史**：执行前务必备份（`cp -r`），执行后需要 `--force` 推送。如果其他协作者已经 clone 了仓库，他们需要重新 clone。
3. **PAT 有效期**：Fine-grained token 最长 1 年，建议设 90 天，到期前续期。
4. **代理端口 10808**：这是本地 SOCKS5/HTTP 代理端口，确保代理软件运行中。
5. **Python 版本**：CI 用 3.12，本地可能是 3.11。本地通过不代表 CI 通过，必须看 CI 结果。
6. **163 邮箱授权码**：用户已明确决定保留旧的，不要强制轮换。但确保代码中只出现 `${SMTP_AUTH_CODE}` 占位符。
7. **AideanCompany 没有测试和 CI**：它目前没有 `.github/workflows/` 和 `tests/` 目录，只需要做凭据清理和推送同步。
8. **Aidean / Aidean_huaweicloud / AideanBot**：在 GitHub 公开 API 中未找到，可能是私有仓库或未创建。执行前确认这些目录是否存在以及它们的 remote URL。
