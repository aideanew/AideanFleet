# AideanFleet 架构

> 更新：2026-10-11（Kernel 重构轮）。本文件描述现状架构；历史演进见 docs/进度与决策.md。

## 1. 分层与 import 边界

```
L0  fleet/kernel      状态内核：goal/todo/claim/lease/attempt/quota/events（只依赖标准库）
L1  fleet/planner     LLM 规划器（依赖 kernel）
L1  fleet/harness     声明式执行体 profile + 流式执行器（依赖 executors.base、core.fleet_toml）
L1  fleet/core/fleet_toml  fleet.toml 配置层（依赖 core.paths）
L2  fleet/runner      Turn Runner：packet/gate/writeback/worker（依赖 L0/L1）
L2  fleet/cli         fleet 命令入口（可依赖一切）
```

规则由 `tests/architecture/test_import_boundaries.py` 守门：
- kernel 不 import 任何 fleet 模块；
- 受控包（kernel/planner/harness/runner）不得 import console/manager/launcher/governance/notify/rel；
- 未列出的旧链路包（console/manager/gates/models/governance/notify/rel/launcher/executors）暂不受限，逐步并入。

旧链路（TaskPack/10 状态机/dispatcher/scheduler/console server）继续工作并与内核共存：
同一进程内两套状态存储互不干扰——旧链路 `data/fleet.db`，内核 `data/kernel.db`。

## 2. Kernel（单写者）

文件：`fleet/kernel/{store,state,kernel,export}.py`，数据库 `data/kernel.db`（SQLite WAL）。

生命周期：`open → claimed → running → verifying → done | blocked | needs_user | superseded`

- **claim/lease**：`claim(todo, worker, lease)` 写认领人与到期时间，同时登记一条未闭合 attempt；
  流式执行中 `renew_lease` 续约；`requeue_expired_leases` 把过期任务收回 open（kill-safe）。
- **transition(todo, TurnResult)** 是唯一写回入口，verdict 决定去向：
  - `done`：仅 verifying 可写；exec 类无 verify 且无证据 → 拒绝（A5）；写回后计费（quota.used+1）；
    goal 下全部 done/superseded → `goal:done`。
  - `successor`：新建同 lineage 的返工 todo；lineage attempt 轮数 ≥ 上限（默认 4）→ 改为 `needs_user`。
  - `blocked` / `needs_user`：等待人工；`reopen(todo, actor)` 人工放回 open。
- **quota**：验证通过并写回才计费；`claimable()` 会跳过额度耗尽角色的任务。
- **events outbox**：所有状态变更同事务写 events 表；`export_events` 导出 JSONL 并标记已发布。
- **allowed_files 并行互斥**：claimable 只返回与在跑任务顶层目录不相交的 todo（推荐每任务一个 git worktree）。

## 3. Turn Runner（fleet worker）

文件：`fleet/runner/worker.py`。每轮：`should_run → claim → packet → harness(流式+续约) → gate → transition`。

- packet = 目标 + todo + allowed_files + verify 命令 + 写回格式（`kernel.packet_for`）。
- gate：`runner/gates.py` 真实执行 verify 命令（cwd=工作区），证据落 `data/evidence/<todo>/`。
- harness 链来自 `fleet.toml [roles.X] harness=[...]`，缺省 `claude → codex → opencode`，
  逐个 detect，全不可用 → 模型直写回退（配置了 planner_client 时，`runner/model_write.py`
  按模型 JSON ops 协议改文件，边界三重校验：workspace 内 + allowed_files + 拒穿透 symlink，
  仍过同一道机器门）；无回退 → blocked（原因可观测，UI 标红）。
- `kind=plan` 的 todo 由 Planner 执行（见 §4）。

## 4. Planner（A2：让 Manager 变真）

文件：`fleet/planner/`。规划本身是 `kind=plan` 的 todo：
组装提示词 → 模型客户端（生产用 models.router 直连池；测试可注入）→ 提取 JSON →
`schema.validate_plan` 硬校验（verify 必须真实命令、依赖无环、id 唯一、白名单必填）→ 写入 kernel。
校验失败 → successor 重试（带上一轮错误）；轮数超限 → needs_user。
对话即控制面（A3）：用户消息可转 `kind=steer` todo，Planner 产出计划 diff。

## 5. Harness Profiles（P3）

文件：`fleet/harness/profiles/{claude,codex,opencode}.yaml`，极小 YAML 子集解析器零依赖。

| 字段 | 语义 |
| --- | --- |
| detect / auth_check | 已安装 / 已登录探测（`fleet doctor` 逐个跑，C5 修复） |
| invoke | 无头调用骨架；prompt 经 stdin 注入 |
| model_protocol | `openai` 才吃模型池（注入 OPENAI_BASE_URL/KEY）；`anthropic` 用宿主自身凭据（C3 口径） |
| output_parser | claude_stream_json / codex_jsonl / opencode_json / plain |
| session_resume / timeout_idle_s | 断点续跑骨架 / 空闲超时 |

## 6. 配置（F3/F4）

- 新链路：`fleet.toml`（嵌套结构，tomllib 解析，密钥只写环境变量名）。
  优先级唯一：**环境变量 > fleet.toml > 内置默认**；`fleet doctor --config` 打印生效值与来源。
- 旧链路：`.env`（七段编号扁平键）继续可用；控制台仍是唯一写者（config.save 白名单）。

## 7. 控制台（投影，P5 方向）

FastAPI（`fleet/console/server.py`）+ Vue3（`fleet/console/web/`，构建产物 `fleet/console/dist` 已入库）。
Kernel 投影端点：`GET /api/kernel/attention | todos | events`、`POST /api/kernel/todos/{id}/reopen`。
首屏语义 = 注意力队列：待决策 / 运行中 / 阻塞 / 刚完成。

## 8. 契约与安装（v2.1）

- **契约唯一源**：packages/contracts/（ADR-002），types.ts 由 scripts/contracts_gen.py 生成（--check 守门）。
- **kernel.db 迁移**：database/migrations/ 唯一源，fleet/kernel/migrate.py 启动时按序应用（schema_version 表）。
- **生产接线**：控制台 /tasks/new → POST /api/kernel/goals → kernel.create_goal_with_plan；
  fleet worker（cmd_worker）注入 planner_client/model_for（ADR-004 选项 C，装配在 fleet/cli/clients.py）。
- **零基础安装**：scripts/installer/（Inno Setup 按用户安装，运行时离线内置，CI 签名流水线）+
  fleet.setup（组件检测/CLI 安装作业）+ /setup 向导三步（装组件 → 密钥 → 登录）。
- **Steer**：kind=steer todo 由 Planner 产出 PlanDiff；step 模式 needs_user 待确认，auto 直接应用。
