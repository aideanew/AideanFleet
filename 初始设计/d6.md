# 一键多 Agent 协作系统设计：可配置基座 + 员工 + 管理员兜底

你的想法完全可行，本质是做一个 **Agent Fleet Orchestrator（多智能体编排器）**：

> 用户只做一件事：准备好文档 + 点一次运行。剩下员工用各自的基座/模型/skills 干活，429/400 由管理员自动或半自动兜底，用户只收结果。

下面是可直接落地的完整方案。

## 1. 总体架构

```python
# 逻辑架构，无需死记，核心就 6 个部件
User Docs -> Planner -> Dispatcher -> [员工A, 员工B, 员工C...] -> Manager(验收+兜底) -> Result
                                          |         |                |
                                      Base Adapter  Base Adapter  Base Adapter
                                      claude/codex/opencode
```

### 1.1 核心概念

1. **Base 基座适配层**：统一封装 `claudecode / codex / opencode`，上层只调 `run(prompt, files, model)`，不关心底层是 CLI 还是 API。
2. **Employee 员工**：`基座 + 模型 + system_prompt + skills + 工作目录 + 权限` 的组合。可同基座不同模型。
3. **Manager 管理员**：独立 agent，有最高权限：重试、换模型、换基座、拆任务、人工介入、合并结果。
4. **Task Pack 任务包**：开发前准备充足的文档，就是这个包。包含目标、上下文、验收标准。
5. **Execution Engine 执行引擎**：一键运行、并行调度、状态机、日志、产物收集。
6. **Error Bus 错误总线**：所有 `429 / 400 / 超时 / 工具失败` 统一上报给 Manager 处理。

### 1.2 为什么这样能省掉问来问去

传统方式是管理员不断追问员工要上下文。新方式是：

* 上下文一次性在 `Task Pack` 里给足，员工无权反问，只许按契约输出 + 报错误码。
* 员工输出强制结构化，管理员做机器验收，不通过就自动打回，不需要开会。

## 2. 基座选型建议

| 角色 | 推荐基座 | 理由 | 典型模型 |
|---|---|---|---|
| 员工A（重构/编码） | `claudecode` | 长上下文、文件编辑稳、skills 强 | `claude-sonnet-4.5` / `claude-opus-4.1` |
| 员工B（编码/测试） | `claudecode` 或 `opencode` | 与A隔离计费，可用便宜模型跑测试 | `claude-haiku-4` / `gpt-5-mini` / `qwen3-coder` |
| 管理员 | `codex` | 推理强、适合验收、切模型方便、便宜 | `gpt-5` / `gpt-5-codex` |
| 备用/省钱 | `opencode` | 可接任何 OpenAI 兼容模型，适合批量 | `deepseek-v3.2` / 本地 `ollama` |

> 关键：**允许同基座不同模型**。例如 A 和 B 都用 `claudecode` CLI，但 A 配 opus，B 配 haiku，成本差 10 倍。

实现上用 Adapter 屏蔽差异：

```python
# agent_fleet/bases/base.py
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class AgentResult:
    ok: bool
    output: str
    error_code: str | None = None  # 429, 400, TIMEOUT, TOOL_FAIL
    error_msg: str = ""
    usage: dict | None = None

class BaseAdapter(ABC):
    name: str
    @abstractmethod
    def run(self, prompt: str, workdir: str, model: str, timeout: int = 600) -> AgentResult:
        raise NotImplementedError
```

```python
# agent_fleet/bases/claude_adapter.py
import subprocess, json
from .base import BaseAdapter, AgentResult

class ClaudeCodeAdapter(BaseAdapter):
    name = "claudecode"
    def run(self, prompt: str, workdir: str, model: str, timeout: int = 600) -> AgentResult:
        # claude -p --model xxx --output-format json
        cmd = ["claude", "-p", prompt, "--model", model, "--output-format", "json"]
        try:
            p = subprocess.run(cmd, cwd=workdir, capture_output=True, text=True, timeout=timeout)
            if p.returncode != 0:
                err = p.stderr or p.stdout
                code = "429" if "429" in err else "400" if "400" in err else "TOOL_FAIL"
                return AgentResult(ok=False, output="", error_code=code, error_msg=err[-2000:])
            data = json.loads(p.stdout)
            return AgentResult(ok=True, output=data.get("result", p.stdout))
        except subprocess.TimeoutExpired as e:
            return AgentResult(ok=False, output="", error_code="TIMEOUT", error_msg=str(e))
```

## 4. 开发前文档准备充足 = Task Pack 模板

一键完成的前提不是模型多强，而是任务包够硬。强制每个任务一个 YAML：

```yaml
# tasks/C-T7.yaml
id: C-T7
title: "3333真实链路"
goal: "复用 http://localhost:3333 完成 SSO→建空间→202→READY→SSE"
context_files:
  - "frontend/lib/api.ts"
  - "frontend/components/AddArticlePanel.tsx"
  - ".docs/API接口文档.md"
constraints:
  - "只允许 3333，严禁 3334"
  - "NEXT_PUBLIC_API_MOCK=false"
  - "不改 backend/docker/globals.css"
acceptance:
  - "URL含3333截图3张"
  - "Network EventStream 含 meta/delta/done 9帧"
  - "pnpm test:unit 43 passed, typecheck 0, build 8/8"
  - "清理 .c-t7-*"
output_contract:
  type: "markdown"
  required_sections: ["改动清单", "命令记录", "证据链", "四要素", "未完成事项"]
  evidence_table_columns: ["编号", "目标", "文件", "命令", "关键结果", "结论", "限制"]
```

员工 system prompt 模板：

```markdown
# prompts/employee-C.md
你是员工C，只做 frontend 真实链路。
规则：
1. 只读 Task Pack 和 context_files，不许反问，不许扩大范围。
2. 所有结论必须有命令输出证据，无证据写 待确认。
3. 遇到 429/400/超时：立即按格式上报，不要自己无限重试：
   ERROR_CODE=429|400|TIMEOUT
   ERROR_MSG=<最后2000字>
   LAST_ACTION=<正在执行的命令>
4. 输出必须符合 output_contract，缺一节即不合格。
5. 端口铁律：只用 3333，netstat 必须贴 3334=0。
```

## 5. 429 / 400 由管理员兜底的完整策略

这是你最关心的点，设计为三级：

```python
# agent_fleet/manager/error_policy.py
import time

def handle_employee_error(employee_cfg, result, attempt):
    code = result.error_code
    # L1: 自动处理
    if code == "429":
        # 1. 换 fallback 模型
        if attempt < len(employee_cfg["fallback_models"]):
            return {"action": "retry_other_model",
                    "model": employee_cfg["fallback_models"][attempt],
                    "wait": 10 * (attempt + 1)}
        # 2. 排队指数退避
        return {"action": "queue_retry", "wait": 60}
    if code == "400":
        # 400 90%是 prompt 太长/参数错，管理员做一次裁剪修复
        return {"action": "manager_fix_prompt",
                "fix": "truncate_context_to_80k + strip_images + retry_once"}
    if code == "TIMEOUT":
        return {"action": "split_task", "fix": "拆成两步重跑"}
    # L2: 管理员接管
    # L3: 通知用户（只收结果，异常才看）
    return {"action": "escalate_to_user"}
```

管理员 prompt 片段：

```markdown
# prompts/manager.md
你是唯一管理员。你负责验收和兜底。
当收到 ERROR_CODE 时：
- 429：先查该员工 fallback_models，按顺序换模型重试；都 429 则等待 60s*次数后重试，最多3次；仍失败则把任务降级为串行排队，并通知用户“限流，已自动排队，预计X分钟”。
- 400：读取员工 LAST_ACTION，若是上下文超长则删历史log/截图只留关键行；若是参数错则按 Task Pack 的 acceptance 修正；只修一次，重试仍400则转人工并附原文。
- 所有处理必须写进《兜底记录表》：时间/员工/错误码/动作/结果。
- 绝不让员工自己循环重试打爆配额。
```

用户侧体验：

```
[一键运行] -> 进度条 A 60% B 100% C 30%
  └ B 报 429 -> 管理员已自动切 gpt-5-mini 重试 (第1次)
  └ C 报 400 -> 管理员已裁剪日志重试
[完成] -> 打开 report.html 收 截图+日志+产物
```

## 6. 一键执行引擎（MVP 50 行可跑）

```python
# agent_fleet/engine.py
import yaml, concurrent.futures
from bases.claude_adapter import ClaudeCodeAdapter
from bases.codex_adapter import CodexAdapter
from bases.opencode_adapter import OpenCodeAdapter

ADAPTERS = {"claudecode": ClaudeCodeAdapter(), "codex": CodexAdapter(), "opencode": OpenCodeAdapter()}

def load_task(task_yaml):
    import pathlib
    return yaml.safe_load(pathlib.Path(task_yaml).read_text(encoding="utf-8"))

def build_prompt(sys_file, task):
    sys = open(sys_file, encoding="utf-8").read()
    return f"{sys}\n\n=== Task Pack ===\n{task}\n\n=== 输出要求 ===\n必须按 output_contract 输出，不得反问。"

def run_employee(emp, task_file):
    task = load_task(task_file)
    adapter = ADAPTERS[emp["base"]]
    prompt = build_prompt(emp["system_prompt_file"], task)
    last_model = emp["model"]
    for attempt in range(1 + emp.get("max_retries", 2)):
        model = last_model if attempt == 0 else emp["fallback_models"][min(attempt-1, len(emp["fallback_models"])-1)]
        res = adapter.run(prompt, emp["workdir"], model, emp.get("timeout", 600))
        if res.ok:
            return {"id": emp["id"], "ok": True, "output": res.output, "model": model}
        # 上报 Manager 策略（简化版：429换模型，400截断重试）
        if res.error_code == "429" and attempt < len(emp["fallback_models"]):
            last_model = emp["fallback_models"][attempt]
            continue
        return {"id": emp["id"], "ok": False, "error_code": res.error_code, "error_msg": res.error_msg}
    return {"id": emp["id"], "ok": False, "error_code": "RETRY_EXHAUSTED"}

def one_click(fleet_yaml="fleet.yaml"):
    fleet = yaml.safe_load(open(fleet_yaml, encoding="utf-8").read())
    emps = {e["id"]: e for e in fleet["employees"]}
    results = {}
    # 极简 DAG：先并行 A/B，再跑 C，最后 manager
    with concurrent.futures.ThreadPoolExecutor(max_workers=3) as ex:
        futs = {ex.submit(run_employee, emps["employee-A"], "tasks/A-T16.yaml"): "employee-A",
                ex.submit(run_employee, emps["employee-B"], "tasks/B-T10.yaml"): "employee-B"}
        for f in concurrent.futures.as_completed(futs):
            results[futs[f]] = f.result()
    results["employee-C"] = run_employee(emps["employee-C"], "tasks/C-T7.yaml")
    # manager 汇总
    mgr = fleet["manager"]
    summary_prompt = open(mgr["system_prompt_file"], encoding="utf-8").read() + f"\n\n员工结果:\n{results}\n请验收并生成 report.html"
    mres = ADAPTERS[mgr["base"]].run(summary_prompt, ".", mgr["model"])
    return {"employees": results, "manager": mres.output if mres.ok else mres.error_msg}
```

## 7. 用户只需要接收结果：交付物规范

强制 `report.html` 包含：

1. 每个员工改动文件清单表
2. 命令记录（含失败原样）
3. 证据链表格
4. 截图 / EventStream 帧 / 产物下载
5. 兜底记录（谁报 429/400，管理员怎么处理的）
6. 未完成事项（不隐藏）

用户操作只有三个按钮：`[一键运行]` `[查看报告]` `[重试失败项]`。
